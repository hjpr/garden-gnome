    Canvas

    The canvas provides a grid-based layout for designing and organizing land into fields, plots, and planting areas. It helps gardeners see which areas are ready to grow and decide where to plant. A shared overview of activity across fields helps coordinate growing, harvesting, tilling, and other work without manually tracking each area separately.

    Viewport

    The viewport is the visible part of the canvas. Navigate across the land without changing its dimensions or the size of the menus.

    Navigation

    Scroll the mouse wheel over the canvas to zoom in or out around the pointer. Hold the middle mouse button and drag to pan; release it to stop. Scrolling over a menu scrolls its content instead of zooming the canvas. Choose Small, Medium, or Large under Settings → Viewport → Menu scaling to resize menus independently.

    Zoom

    Proposed zoom policy: start at 100%, with a default range of 25%–800% for home gardens. Clamp zoom at those limits. Preferences → Appearance & behavior lets users change the minimum and maximum; the range must include 100%. If a new limit excludes the current zoom, move to the nearest allowed zoom without changing the drawing.

    At 100%, one grid-cell side represents the distance entered under Settings → Measure → Scale. The bottom-left scale always describes one currently visible grid-cell side, not the whole viewport. Keep grid spacing between 30 and 60 screen pixels: at each doubling of zoom, halve the distance represented by a cell; at each halving of zoom, double it. Grid lines remain anchored to the same canvas origin. These display changes do not alter land dimensions, the configured base scale, or the snapping target.

    Zoom breakpointDistance per grid-cell sideExample: base scale 4 ft
    25%4 × base scale16 ft
    50%2 × base scale8 ft
    100%Base scale4 ft
    200%½ × base scale2 ft
    400%¼ × base scale1 ft
    800%⅛ × base scale0.5 ft

    Between breakpoints, zoom is continuous while the distance per cell stays fixed. The same doubling rule continues beyond the defaults when custom limits allow it. Wheel zoom, middle-button panning, and adaptive grid spacing are specified here for the drawing engine; the prototype currently previews menu scaling and appearance controls.

    Layers

    Layers lets gardeners choose the active layer to draw on and organize land into fields, plots, and areas. Fields mark property boundaries; multiple fields are allowed, but their areas cannot overlap. Plots represent major sections within a field, staying entirely inside its boundary without overlapping other plots. Areas define the actual growing spaces within plots, with properties such as rows or mounds that support planting calculations using growing instructions from seed references.

    LayerDescription
    FieldA top-level layer marking a property boundary. Multiple fields can be drawn, but their areas cannot overlap.
    PlotA major section within a field, such as vegetables or flowers. Must stay entirely within its parent field and cannot overlap another plot. Select a field before adding a plot to it.
    AreaThe actual growing space within a plot. Flat, row, or mound properties support planting calculations based on growing instructions from seed references. Stays inside its parent plot. Select a plot before adding an area to it.
    ReferenceAn image used to trace and scale the layout. Added at the bottom of the layer stack, outside the Field/Plot/Area hierarchy; each new reference goes beneath existing layers.

    Settings

    Measure sets units and the grid scale at 100% zoom. Snapping chooses the alignment target, while Viewport controls menu sizing independently of canvas zoom.

    PropertyDescription
    UnitsChoose ft or m. Scale and Reference known-distance labels use these units; changing units in the prototype does not convert entered values.
    ScaleEnter the positive distance represented by one grid length. The label shows the selected units, such as Scale (ft), and the canvas scale updates as you type. Blank or invalid values show a dash.
    SnappingTurn snapping on or off with the checkbox. Choose Grid or Drawing from Snap to; the dropdown is disabled while snapping is off and retains its selection. When Snap to is Drawing, snapping attempts to snap to the last drawing selected.
    Menu scalingSmall (85%), Medium (100%, default), or Large (115%). Changes floating menu sizes without changing the grid, drawing dimensions, or viewport zoom.

    Name the field, choose its outline color, and record drainage and soil sample results. The seed engine will use the soil information to flag crops that may grow poorly in the field’s soil.

    PropertyDescription
    NameRename the field with the pencil icon.
    ColorChoose the field outline color from the dropdown.
    Soil drainageExcessive, good, moderate, fair, or poor.
    Soil managementEnter pH, P, K, Ca, Mg, CEC, EC, and organic matter from soil samples.

    Plot properties

    Name the plot and choose its outline color and fill pattern.

    PropertyDescription
    NameRename the plot with the pencil icon.
    ColorChoose the plot outline color from the dropdown.
    PatternChoose none, dots, crosshatch, or crosses. A visual fill, separate from ground layout.

    Area properties

    Name the area and choose Flat, Row, or Mound from the Planting type dropdown under Options. The section below the divider shows settings for that type. Generated features stay inside the area boundary.

    Planting typeDescription
    FlatA continuous planting surface within the area boundary. No additional settings yet.
    RowNumeric inputs for row width, spacing, and direction in degrees (0–360°).
    MoundNumeric inputs for mound diameter and spacing.

    Reference properties

    Name the reference layer, choose its color and a local image, and enter the known distance for its Reference Line. Select the layer by its name or gear to enable Reference tools. Image movement and distance-based scaling are planned drawing behavior.

    PropertyDescription
    NameRename the reference layer with the pencil icon.
    ColorChoose a color for the reference layer. The prototype retains the selection per layer without tinting the image.
    ImageChoose a local PNG, JPEG, or WebP image. It stays in the browser and is cleared on reload.
    Known distanceThe real distance between the Reference Line endpoints. The label shows the Canvas units in parentheses: ft or m. Used to scale only the selected image.

      Build API

      Geometry

      Geometry is the base object holding points, lines, circles, closed shapes, and their ID counters. FieldGeometry, PlotGeometry, and AreaGeometry inherit this structure. These are proposed storage structures, not yet implemented.

      Shape

      Geometry:
  last_ids:
    type: object
    fields:
      points: {type: integer, minimum: 0, default: 0}
      lines: {type: integer, minimum: 0, default: 0}
      circles: {type: integer, minimum: 0, default: 0}
      shapes: {type: integer, minimum: 0, default: 0}
  points: {type: list, items: Point, default: []}
  lines: {type: list, items: Line, default: []}
  circles: {type: list, items: Circle, default: []}
  shapes: {type: list, items: ClosedShape, default: []}
      AttributeMeaning
      last_idsSequential ID counters for this geometry instance. Each counter starts at zero and retains the highest assigned number after deletion.
      last_ids.pointsHighest assigned point ID number.
      last_ids.linesHighest assigned line ID number.
      last_ids.circlesHighest assigned circle ID number.
      last_ids.shapesHighest assigned closed-shape ID number.
      pointsPoint records. Starts empty.
      linesLine records referencing points. Starts empty.
      circlesCircle records. Starts empty.
      shapesClosedShape records grouping lines into enclosed regions. Starts empty.

      Every Geometry instance owns its own collections and counters; they are not shared between instances or subclasses.

      AttributeMeaning

      dimensionsAreaGeometry’s dimensions for each planting arrangement.
      dimensions.flatFlat arrangement settings. Starts as an empty object.
      dimensions.rowRow width, spacing, and direction. Each value starts as null.

      The parent owns the geometry directly: Field.outline is FieldGeometry, Plot.outline is PlotGeometry, and Area.outline is AreaGeometry. Properties objects hold non-geometric menu settings, not dimensions or geometry objects.

      Area dimensions

      The menu’s dimension inputs edit Area.outline.dimensions, even though they appear in the properties panel. AreaProperties.planting_type selects which type’s controls are shown and which dimensions are active. Switching types preserves the other dimensions.

      Blank numeric inputs become null; entered values are finite numbers. Direction accepts 0 through 360 degrees, inclusive. The nonnegative limits mirror the menu, not a guarantee that zero-sized features can be generated. Required dimensions and stricter drawing checks remain for the drawing functions.

      The mockup does not label length units or define whether spacing is measured between edges or centers. Those conventions, and the reference axis for direction, remain open. No automatic unit conversion is specified.

      ID counters

      Each counter stores the highest number assigned for that type, not the number of records currently present. Zero means none have been assigned. The next candidate uses the counter plus one, with the existing type prefix:

      points: point-{number}
lines: line-{number}
circles: circle-{number}
shapes: shape-{number}

      For example, when last_ids.points is 6, the next candidate is point-7. Once assigned, the point counter becomes 7; the other counters stay unchanged. Deleting a point does not lower its counter or make its number available again.

      Store the counters with the geometry so later editing continues the sequence. Each counter must be at least the highest assigned suffix of its type, including deleted records. IDs are local to a Geometry instance: separate instances may both contain point-1, so a reference outside the instance also needs its owning context.

      This defines stored ID bookkeeping only. Collision checks, counter updates in drawing functions, and handling imported or concurrent edits will be designed later; a counter alone does not enforce uniqueness.

      Point

      Point:
  id: {type: string, required: true}
  x: {type: number, required: true}
  y: {type: number, required: true}
      AttributeMeaning
      idThe point’s identifier within this geometry instance.
      xPosition along the canvas’s x axis.
      yPosition along the canvas’s y axis.

      A point is a position with its own identity. Different IDs may have identical coordinates, so a line’s start and end can sit on top of each other without becoming the same point. Reusing an ID means sharing one point; moving it changes every line or circle that references it.

      Line

      Line:
  id: {type: string, required: true}
  start: {type: Point.id, required: true}
  middle:
    type: map
    keys: middle_1, middle_2, ...
    values: Point.id
    default: {}
  end: {type: Point.id, required: true}
      AttributeMeaning
      idThe line’s identifier within this geometry instance.
      startID of the first point.
      middleOptional intermediate point IDs, keyed as middle_1, middle_2, and so on in traversal order. These are vertices rather than calculated halfway positions. Starts empty.
      endID of the final point.

      A line follows straight segments from start through its middle points to end. With no middle points, this is a single straight segment.

      Number middle keys consecutively from 1 with no gaps, and read them by numeric suffix, not YAML key order or alphabetical order. Consecutive vertices must have different coordinates; the final endpoint may return to the start to close a shape. A line itself has no fill pattern.

      Circle

      Circle:
  id: {type: string, required: true}
  center: {type: Point.id, required: true}
  radius: {type: number, required: true, exclusive_minimum: 0}
  pattern:
    type: string
    nullable: true
    default: null
    allowed: [null, dots, crosshatch, crosses]
      AttributeMeaning
      idThe circle’s identifier within this geometry instance.
      centerID of the center point.
      radiusFinite, positive distance from the center to the boundary, in the same units as the coordinates.
      patternVisual fill: dots, crosshatch, or crosses. Defaults to null for an empty fill.

      Closed shape

      ClosedShape:
  id: {type: string, required: true}
  lines: {type: list, items: Line.id, required: true, minimum_items: 1}
  pattern:
    type: string
    nullable: true
    default: null
    allowed: [null, dots, crosshatch, crosses]
      AttributeMeaning
      idThe closed shape’s identifier within this geometry instance.
      linesOne or more line IDs in boundary order. Each line is traversed from its start through its middle points to its end.
      patternVisual fill for the enclosed region: dots, crosshatch, or crosses. Defaults to null for an empty fill.

      A closed shape groups lines into one filled region. Its points are reached through those lines, so a second point list is unnecessary.

      Each line’s end must meet the next line’s start by coordinates, and the final end must meet the first start. Matching coordinates close the boundary even when the point IDs differ; they do not merge the points. One line with middle points can form the whole boundary.

      For this first version, the boundary must enclose nonzero area without crossing or retracing itself. The shape owns one pattern; its points and lines do not. Holes are left for a later pass.

      Geometry example

      A proposed Field record whose outline contains a dotted region and a crosshatched circle. The region uses two lines; its final point has the same coordinates as its first but a different ID.

      id: north-field
name: North field
Plots: []
outline:
  last_ids:
    points: 6
    lines: 2
    circles: 1
    shapes: 1
  points:
    - {id: point-1, x: 0, y: 0}
    - {id: point-2, x: 12, y: 0}
    - {id: point-3, x: 12, y: 8}
    - {id: point-4, x: 0, y: 8}
    - {id: point-5, x: 0, y: 0}
    - {id: point-6, x: 6, y: 4}
  lines:
    - id: line-1
      start: point-1
      middle:
        middle_1: point-2
        middle_2: point-3
      end: point-4
    - id: line-2
      start: point-4
      middle: {}
      end: point-5
  circles:
    - id: circle-1
      center: point-6
      radius: 2
      pattern: crosshatch
  shapes:
    - id: shape-1
      lines: [line-1, line-2]
      pattern: dots
